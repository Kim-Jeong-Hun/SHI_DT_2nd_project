*[회의록] 선박 수주 예측 진행 공유 · 파이프라인 자동화 제안* (녹음 '장평동 21-10', 9분 39초 · 정리 최현서)
_음성인식 받아쓰기 기반 요약 — 잘 안 들린 부분은 ❓ 표시_

*한 줄 요약*
선종별 수주 예측 현황(데이터·변수·성능) 공유 + 선종별 분석을 하나의 공통 파이프라인(마스터 테이블 → 학습 → 피처 제거 → 재학습)으로 묶고 Kedro·Airflow·Docker로 월간 자동 수집·분석까지 가자는 제안

*1. 현재 상태*
• 예측 대상: 선종별 월별 수주 규모(2015~) — 단위가 선종마다 다름(유조선·벌크 DWT 백만 단위 / 컨테이너 TEU / 가스 CBM)
• 넣은 변수: 선종별 운임 · 세계 선복량 · 신조선가
• 넣을 변수: 국제 원자재가 · 무역정책 불확실성 지수 · 싱가포르 벙커유가(선박 연료 대표 지표) · 지정학 위험 지수 · 무역갈등 지수(월별 자료 확인)

*2. 성능*
• 오차 지표 약 64%(낮을수록 좋음, ❓지표명 — MAPE로 추정) → 목표 30% 이하
• 잘 나온 모델 약 60%, 안 나온 모델 90~100% / 하이퍼파라미터 튜닝 전
• 추세는 따라가나 값은 못 맞힘 / 2025→26 급변 구간 — 관세·무역갈등 영향 추정(미성 조사) → 무역갈등 지수 추가 예정

*3. 발견: 선종별 핵심 변수가 다름*
• 컨테이너선: 신조선가가 가장 중요("비싸면 안 짓는다")
• 벌크선: 철광석 가격이 중요(철광석을 나르는 배)
→ 발표에서 입체적으로 설명 가능

*4. 공통 파이프라인 방식*
① 공통 변수로 마스터 테이블 생성(생성 원칙 정리됨) ② EDA로 일괄 확인(석탄·곡물·철광석 등 다중공선성 높음) ③ 1차 학습 후 평가 지표 보고 불필요 피처 제거 ④ 재학습·결론
→ 이후엔 마스터 테이블에 데이터만 추가하면 되는 구조

*5. 자동화 제안*
• 선종별 분석 5개가 같은 처리 방식 → 월별 데이터라 5년이면 60회 반복
• 월 1회 자동 수집 API(크롤링) → 자동 분석까지 연결
• Kedro 파이프라인 → Airflow 월간 스케줄 → Docker로 패키징 ("배운 걸 다 쓰는 구조")

*할 일*
• 분석팀: 추가 변수 반영 · 하이퍼파라미터 튜닝 · 오차 30% 이하
• 미성: 2025~26 급변 원인(무역갈등 지수) 확보
• 현서·정훈: 마스터 테이블→피처 제거→재학습 자동화, Kedro 파이프라인 + Airflow 월간 DAG + 수집 API 설계
• 전원: 각자 분석 결과 공유

*참고(현서)*: 북극항로에 만든 Kedro + Airflow + Docker 구조를 선종 파라미터로 재사용 가능 / 이전 시간순 검증에서 운임 모델이 '최근 3년 평균'보다 못했음(MAE 101.9~120.7 vs 69.0) → 단순 기준선과 비교 권장
