[A2] 선박 수주 예측 서빙 API + 3D 라이브 관제 화면 (최현서 · 10/06)

■ 요약
- 팀 보고서(scripts/분석/2026_독립검증.py 산출)를 그대로 읽는 FastAPI 서빙 계층 추가 — 재학습 없음, 보고서 파일이 바뀌면 다음 요청부터 자동 반영
- /ship 을 북극항로 관제 수준의 3D 화면으로 재구성(three.js 야간 조선소). 기존 2D 대시보드는 /ship/dashboard

■ 엔드포인트
- GET /ship/meta — 선종별 선택 모형·2026 월별 sMAPE vs 기준선·노트북 테스트 월/분기/반기 sMAPE
- GET /ship/forecast?ship=&horizon=1|3|6 — 예측기준일 2026-09-30 운영 예측, 목표월, 경험적 범위(2026 백테스트 실제÷예측 10–90% 분위), 기준선(최근 3개월 평균), 입력 수주 게시일, 2026 백테스트 월별
- 잘못된 선종·선행개월은 400(한국어 메시지), 모든 호출은 예측 로그에 기록

■ 3D 관제 화면 구성
- 선종 5개 = 레인, 2021-01~2026-08 월 확정 수주 = 기둥(선종별 상대 높이: 단위가 TEU·DWT·CBM으로 달라서)
- 2026 백테스트 예측 = 고리, 실제와의 차이 = 빨간 선 / 운영 예측 = 빛기둥, 범위 = 반투명 원통, 기준선 = 호박색 원반
- 골리앗 크레인이 선택한 목표월로 이동, 선박이 레인을 따라 항해, 선택 시 카메라 호 비행·음파 고리·불꽃
- 시네마틱 투어 7장면(전경 → 선종별 +1→+3→+6 → 2026 검증), 과소 예측 경향이면 경보 배너, 관제 로그에 API 호출·예측 기록
- 60초마다 보고서 수정 시각 확인 → Kedro 갱신 감지 시 자동 재적재

■ 운영 파이프라인
- Kedro ship_orders: 팀 스크립트 실행 → data/01_raw/ship 보고서·이력 갱신
- Airflow shi_ship_order_pipeline: 매월 5일 06:00 → kedro run → /ship/meta 확인

■ 확인할 점 (그대로 보고)
- 오늘 팀 스크립트를 다시 돌린 보고서가 Drive 사본과 다름: 컨테이너선 선택 모형 랜덤 포레스트 → 최근3개월 평균(기준선과 동일), 가스 운반선 랜덤 포레스트 → 1차 선형회귀(2026 sMAPE 0.697 → 0.600), 케미컬 탱커 평가월 6 → 7개월. 수주실적 원천 갱신(10/05) 또는 랜덤 포레스트 비결정성으로 추정, 원인 미확정
- 2026 백테스트에서 전 선종 과소 예측(실제÷예측 중앙값 1.6~4배) — 범위가 예측값보다 위에 놓이는 경우가 있음(예: 벌크선 +6)
- 벌크선·유조선·가스 운반선은 2026 월별 sMAPE가 기준선보다 나쁨
