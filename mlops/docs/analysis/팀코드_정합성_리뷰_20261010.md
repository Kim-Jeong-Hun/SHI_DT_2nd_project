## 결론 먼저

1. 누수 방지는 잘 되어 있다. 학습 라벨은 항상 자료마감월 D 이하이고, 계열 내 상관 선택도 학습행만 쓰며, 결측을 0으로 채우지 않는다.
2. 가장 큰 문제는 같은 프로젝트 안에 정보 규칙이 다른 예측 경로가 세 개 있다는 점이다. 노트북 숫자(분기 12.5% 등)와 웹 서비스 예측이 서로 다른 모형에서 나온다.
3. 노트북 4절(2025~2026 분기·반기 성적)에는 기준선이 없다. 같은 달로 기준선을 다시 계산하면 컨테이너선 반기 오차는 기준선(9.4%)이 모형(13.3%)보다 낮다.

## 위배·불일치 (중요도 순)

### 1. [높음] 예측 경로 3개가 서로 다른 정보 규칙을 쓴다

| 경로 | 쓰는 곳 | 예측 대상 | 외부지표 | 수주 이력 |
|---|---|---|---|---|
| A. h+6 (`publication_lag_forecast`) | 선종별 노트북 2~5절, 기획서 분기·반기 수치 | 기준월 C의 3개월 뒤(D=C-3 → D+6) | 공통 D(=C-3) | 달력 D·D-1·D-2, 게시일 제한 없음 |
| B. 1개월 모형 (`2026_독립검증.frozen_choice`) | `2026평가`, handoff 표(컨테이너선 0.303 vs 0.223) | 다음 달(t) | 1~2개월 시차 고정 | t-2/t-3, 게시일 확인 |
| C. 직접 1·3·6개월 (`operational_forecast`) | 웹 서비스 `/ship/forecast`, MLflow 운영 모델 15개 | 1·3·6개월 뒤 | 쓰지 않음 | 게시일 확인된 것만 |

- 지침 1절(−3개월 정보로 +3개월 예측)에 맞는 것은 A뿐이다. B는 1개월 앞 예측이고 외부지표를 1~2개월 전 값으로 써서 지침보다 정보가 신선하다.
- 발표에서 "랜덤 포레스트·변수 20개"(A)를 설명하면서 서비스 화면은 수주 이력만 쓰는 C를 보여 주면 평가자가 불일치를 지적할 수 있다.
- 제안: 발표·서비스의 정본 경로를 하나로 정하고, 나머지는 '보조 실험'으로 명시.

### 2. [높음] 2025~2026 분기·반기 성적에 기준선이 없다

노트북 4.1절과 같은 17개월(목표월 2025-04~2026-08), 같은 분기 5개·반기 2개로 '확보월까지 3개월 평균' 기준선을 다시 계산했다(마스터 CSV, 게시일 제한 없음 = 노트북과 같은 가정).

| 선종 | 월별 모형 / 기준선 | 분기 모형 / 기준선 | 반기 모형 / 기준선 |
|---|---|---|---|
| 컨테이너선 | 57.4 / 56.8 | 12.5 / 16.3 | 13.3 / 9.4 |
| 벌크선 | 64.2 / 80.0 | 44.5 / 57.2 | 54.1 / 64.8 |
| 유조선 | 85.1 / 83.2 | 73.2 / 87.1 | 99.3 / 98.7 |
| 케미컬 탱커 | 79.6 / 74.1 | 58.1 / 63.6 | 45.6 / 54.1 |
| 가스 운반선 | 93.4 / 88.8 | 81.7 / 94.0 | 76.6 / 97.7 |

(sMAPE %, 낮을수록 좋음. 기준선은 리뷰어 재계산값이라 팀 코드로 다시 확인 필요.)

- 월별로는 5개 선종 중 4개에서 기준선이 모형과 같거나 낫다. 분기 누적에서는 5개 모두 모형이 낫다.
- 컨테이너선 반기는 기준선이 더 낫다. 반기 표본이 2개라 판단에 쓰기 어렵다는 점도 함께 적어야 한다.
- 지침 2절 '기준선과 반드시 비교'에 따라 4.1 표에 기준선 열을 두는 것을 제안한다.

### 3. [높음] 벌크선은 검증에서 기준선을 못 넘었는데 모형이 선택된다

2022~2024 fold 평균 sMAPE(%):

| 선종 | 최근 3개월 평균 | 최종 선택 모형 |
|---|---|---|
| 컨테이너선 | 109.9 | 85.7 (랜덤 포레스트 20개) |
| 벌크선 | 72.4 | 74.7 (랜덤 포레스트 21개) |
| 유조선 | 83.6 | 74.4 |
| 케미컬 탱커 | 73.9 | 72.5 |
| 가스 운반선 | 58.4 | 53.2 |

- `select_candidates`는 세 ML 모형 중에서만 고르고 기준선은 후보에 넣지 않는다. 벌크선은 기준선이 1.4%p 더 나은데도 랜덤 포레스트가 최종이 된다.
- 케미컬 탱커는 1.4%p 차이로 거의 같다.
- 지침 3절 2항('기준선을 못 이기면 그대로 적는다')에 따라, 기준선을 후보에 넣거나 노트북에 '벌크선은 검증에서 기준선 미달'을 명시하는 것을 제안한다.

### 4. [중간] 10/08 승인 평가 체계와 Drive 코드가 다르다

- `분석전략.txt`(10/08 사용자 승인)는 A Train 48개월 / B Train 60개월, Validation 3개월 창, 반감기 12개월 가중 WAPE, Test 3개월 1회를 기준으로 한다.
- Drive 노트북·코드(10/06)는 2022~2024 연도 fold, sMAPE, 변수 제거(1%p·3개 연도 중 2개) 체계다.
- 아카이브 A19의 민규 님 10/07 결과(Test WAPE 벌크 74.51% 등)는 새 체계의 숫자라 노트북·기획서 숫자와 직접 비교할 수 없다.
- 제안: 새 체계 코드를 Drive에 올리고, 기획서·서비스가 어느 체계 숫자를 쓰는지 하나로 정한다. `PROJECT_GUIDELINES.md`의 변수 제거 규칙(3개 연도 중 2개)과 현재 성능(분기 10%·반기 8%)도 갱신이 필요하다(현서 담당 문서).

### 5. [중간] 수주 게시일 규칙이 경로마다 다르다

- 경로 A(노트북)는 `수주게시일`을 모두 NaT로 두어 게시일 제한을 끈다(노트북 1.2절·`공개시차_6개월_컨테이너선.py` 72~75행). 노트북 머리말에도 '개별 기사 게시일로 사용을 막지 않는다'고 적혀 있다.
- 경로 B·C는 게시일이 확인된 수주만 쓴다.
- 아카이브 A21 정정의 '팀 모델은 이미 게시일 기준'은 경로 B·C에만 맞는다. 기획서의 '시점 정직성' 강조와 노트북 가정이 다르게 읽히지 않도록 문구를 맞추는 것을 제안한다.

### 6. [중간] '2026 독립 평가' 표현

- handoff·기획서는 '2026-01~08 독립 평가(모델 선택에 미사용)'로 쓴다.
- 코드 자신의 기록(`2026_독립검증.json`의 '제약')과 `분석전략.txt`(10/08)는 '이미 결과를 봤으므로 독립 테스트가 아니다'로 쓴다.
- 발표 문구를 '회고적 평가'로 통일하는 것을 제안한다.

### 7. [중간] 2025년 라벨을 선택에 쓰는 경로가 있다

- 지침·`분석전략.txt` 3·6·7절: 2025년은 선택·튜닝에 쓰지 않는다.
- `2026_독립검증.frozen_choice`와 `operational_forecast.select_direct`는 2022~2025 네 해 fold로 선택한다(2026을 보류하기 위한 설계).
- 의도된 설계라면 문서에 '2026 보류 평가용 경로는 2025까지 선택에 사용'이라고 예외를 적어 두면 된다.

### 8. [중간] 변수 사전과 코드 21건 불일치 (테스트 실패)

`tests/test_dictionary_audit.py::test_current_workbook_matches_project_rules` 실패. 사전은 5선종 모두 'O'(사용)인데 코드에는 없는 후보:

- 직전3개월누적수주량, month, month_sin, month_cos (5선종 × 4 = 20건)
- 탄소배출권가격_월평균(EUR/tCO2e) (컨테이너선 1건)

사전을 '-'(후보 아님)로 고치거나 코드에 넣어야 한다. Drive 사전은 10/08에 65→83행으로 바뀌었으므로 최신 사전으로 다시 돌려 볼 필요가 있다.

### 9. [낮음] 월별 sMAPE와 0수주 월

- 실제가 0인 달에 예측이 양수면 sMAPE가 200%로 고정된다. 컨테이너선은 2015~2024 120개월 중 17개월이 0이다.
- 월별 sMAPE가 0수주 월에 크게 좌우되므로, 10/08 WAPE 전환의 근거로 이 점을 기록해 두면 좋다.

### 10. [낮음] 노트북 세부

- EDA 1.1 기술통계 범위가 2024-12까지로, 변수 선택 검증 구간(2022~2024)이 들어간다. 1.2·1.3절은 첫 검증 시점 이전만 쓰므로 1.1도 맞추는 것이 일관적이다.
- 1.1 품질표의 수주 열(`수주용량_최근확정1개월차`)과 모형이 쓰는 열(`수주용량_확보월`)이 다르다.
- 컨테이너선 노트북만 품질표 라벨이 '2개월전용량관측월수'로 남아 있다(다른 선종은 '최근확정1개월차'로 고쳐짐).
- 2024 fold는 7개월, 2022·2023 fold는 12개월인데 fold 평균을 같은 가중으로 낸다. 설명 한 줄이 있으면 좋다.

## 잘 지켜진 것

- 시간순 분할만 사용, 무작위 분할 없음
- 학습 라벨 ≤ 자료마감월 D (`eligible_training`), 연도별 재현(5절)에서 내부 fold가 미래 목표를 쓰면 즉시 오류를 내는 검사
- 미국 TPU·세계 거시·지정학 계열 대표값 선택을 매 예측 시점의 학습행으로만 계산
- 결측 수주를 0이나 직전값으로 채우지 않음, 이상치(대형 발주) 유지
- 단위 변환 없음(TEU·DWT·CBM 그대로), 연간 선복량은 다음 해 1월부터 사용(merge_asof backward)
- 변수 제거 규칙(평균 1%p 개선 + 3개 연도 중 2개)이 경로 A에 그대로 구현됨

## 회의 안건 제안 (팀 코드는 고치지 않음)

1. 발표·서비스 정본 경로 하나 정하기 (A·B·C 중)

3. 선택 후보에 기준선 포함 여부 (벌크선 처리)

5. '독립 평가' → '회고적 평가' 문구 통일, 게시일 가정 문구 통일
6. 변수 사전 21건 정리
